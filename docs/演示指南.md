# 演示指南

## 1. 演示目标

本指南用于演示 AI API Test Platform / AI 接口自动化测试平台 `v0.1.0-mvp` 的完整 MVP 主流程。

当前演示范围：

- 项目管理
- 环境配置
- Swagger/OpenAPI 或 curl 导入
- 接口资产查看
- mock AI 测试用例生成
- 测试用例管理
- Pytest + Requests 执行
- 执行结果和测试报告查看

当前演示不包括：

- 真实 AI 大模型接入
- Knife4j / Swagger UI `doc.html` 页面地址自动解析
- 在线接口文档 URL 导入与 AI 辅助解析
- 复杂接口依赖编排
- 权限系统和登录系统
- CI/CD 或生产级部署

## 2. 启动 MySQL

确保本地 MySQL 8.0 已启动。

默认数据库配置：

```text
HOST: 127.0.0.1
PORT: 3306
DATABASE: ai_api_test_platform
USER: ai_test
PASSWORD: ai_test
```

## 3. 初始化数据库

在项目根目录执行：

```bash
mysql -uroot -p123456 < D:\aiTest\ai-api-test-platform\database\init.sql
```

如果 PowerShell 不支持 `<` 重定向，可以执行：

```powershell
& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -uroot -p123456 -e "source D:/aiTest/ai-api-test-platform/database/init.sql"
```

初始化后应存在 9 张核心表：

```text
project
environment
api_document
api_endpoint
test_case
execution_task
execution_result
test_report
ai_analysis_record
```

## 4. 启动后端

```bash
cd backend
.venv\Scripts\activate
uvicorn app.main:app --reload
```

后端默认地址：

```text
http://127.0.0.1:8000
```

健康检查：

```bash
curl http://127.0.0.1:8000/api/v1/health
```

期望返回：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "status": "ok"
  }
}
```

## 5. 启动前端

```bash
cd frontend
npm install
npm run dev
```

前端默认地址：

```text
http://127.0.0.1:5173/
```

前端通过 Vite proxy 将 `/api/v1` 转发到后端 `http://127.0.0.1:8000`。

## 6. 创建项目

1. 打开 `http://127.0.0.1:5173/`。
2. 进入“项目管理”页。
3. 点击“新建项目”。
4. 填写项目名称、负责人和描述。
5. 保存项目。
6. 在项目列表中点击“进入工作区”。

## 7. 配置环境

1. 进入“环境配置”页。
2. 点击“新建环境”。
3. 配置环境名称。
4. 配置 `base_url`。
5. 配置公共 headers。
6. 配置 `auth_config_json`、`timeout_seconds`、`retry_count`。
7. 保存环境。

本地演示可以使用：

```text
base_url: http://127.0.0.1:8000
```

## 8. 导入 Swagger/OpenAPI 或 curl

进入“接口导入”页，选择一种方式导入：

Swagger/OpenAPI JSON 内容：

- 将 OpenAPI JSON 粘贴到输入框。
- 点击导入。

curl 文本：

- 将 curl 命令粘贴到输入框。
- 点击导入。

验收示例文件：

```text
examples/mvp_acceptance/openapi_health.json
```

当前暂不支持直接输入 Knife4j / Swagger UI 的 `doc.html` 页面地址并自动解析。该能力放到第 9 阶段。

## 9. 查看接口资产

1. 进入“接口列表”页。
2. 查看接口名称、请求方法、接口路径、接口分组、鉴权状态和启用状态。
3. 点击“详情”进入接口详情页。
4. 查看 headers、query params、path params、body、response、examples 等结构化信息。

## 10. 生成 mock AI 测试用例

1. 进入“AI 用例生成”页。
2. 选择接口。
3. 点击生成。
4. 页面会显示“当前为 mock AI 用例生成”。
5. 后端会生成 `normal`、`exception`、`boundary`、`auth` 四类基础用例。

当前 AI 为 mock，不调用真实大模型，不生成自由 Python 代码。

## 11. 保存和管理测试用例

1. 进入“测试用例管理”页。
2. 查看 AI mock 生成的测试用例。
3. 可以编辑请求参数、断言规则和变量。
4. 可以启用或禁用测试用例。

测试用例保存到：

```text
test_case
```

## 12. 执行测试

1. 进入“执行报告”页。
2. 选择环境。
3. 选择测试用例。
4. 点击“执行测试”。
5. 后端会生成临时 Pytest 工程并调用 Pytest 执行。

生成工程位置：

```text
storage/generated/project_{project_id}/execution_{task_id}/
```

生成出来的测试工程不会进入：

```text
backend/app
```

## 13. 查看执行结果

执行完成后，页面会展示：

- 执行任务状态
- 总数
- 通过数
- 失败数
- 每条用例执行结果
- 基础错误信息
- 报告路径
- 日志路径
- 生成工程路径

执行数据保存到：

```text
execution_task
execution_result
test_report
```

## 14. 查看测试报告

测试报告保存到：

```text
storage/reports/execution_{task_id}/report.html
```

执行日志保存到：

```text
storage/logs/execution_{task_id}/pytest.log
```

当前报告使用 pytest-html，暂不引入复杂 Allure 报告。

## 15. 演示结论

`v0.1.0-mvp` 已跑通从接口导入、接口资产保存、mock AI 用例生成、测试用例管理、Pytest + Requests 执行到报告查看的基础闭环。

当前版本适合演示和继续迭代。
