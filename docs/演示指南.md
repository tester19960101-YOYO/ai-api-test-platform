# 演示指南

## 1. 演示目标

演示 AI API Test Platform 的 MVP 主流程，以及第 9 阶段新增的多形态接口输入导入能力、第 10 阶段新增的鉴权配置与业务断言能力。

演示范围：

- 项目管理
- 环境配置
- 在线接口文档 URL / OpenAPI JSON / curl / 接口路径导入
- 接口导入预览、筛选、编辑确认和保存
- 接口资产查看
- mock AI 测试用例生成
- 测试用例管理
- Pytest + Requests 执行
- 执行结果和测试报告查看
- 环境级 token / cookie / header 鉴权配置
- 业务断言结果查看

## 2. 启动 MySQL

确保本地 MySQL 8.0 已启动。

默认连接：

```text
HOST: 127.0.0.1
PORT: 3306
DATABASE: ai_api_test_platform
USER: ai_test
PASSWORD: ai_test
```

## 3. 初始化数据库

```bash
mysql -uroot -p123456 < D:\aiTest\ai-api-test-platform\database\init.sql
```

PowerShell 可使用：

```powershell
& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -uroot -p123456 -e "source D:/aiTest/ai-api-test-platform/database/init.sql"
```

## 4. 启动后端

```bash
cd backend
.venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```

健康检查：

```bash
curl http://127.0.0.1:8000/api/v1/health
```

## 5. 启动前端

```bash
cd frontend
npm install
npm run dev
```

访问：

```text
http://127.0.0.1:5173/
```

## 6. 创建项目

1. 进入项目管理页。
2. 点击新建项目。
3. 填写项目名称、负责人和描述。
4. 保存项目。
5. 在项目列表中进入项目工作区。

## 7. 配置环境

1. 进入环境配置页。
2. 创建环境。
3. 配置 `base_url`、headers、auth 配置、timeout、retry。
4. 保存环境。

本地演示可使用：

```text
base_url: http://127.0.0.1:8000
```

第 10 阶段可配置：

- `auth_type`：`none`、`bearer`、`token`、`cookie`、`custom`
- Token：执行测试时自动写入鉴权请求头
- Cookie：执行测试时自动写入 Cookie 请求头
- `headers_json`：环境公共请求头
- `auth_config_json`：扩展鉴权配置
- `timeout_seconds` 和 `retry_count`

当前不支持自动 token 刷新、自动登录、验证码、SSO 或浏览器自动化登录。

## 8. 导入接口

进入接口导入页，支持以下输入：

- 在线 OpenAPI/Swagger JSON URL，例如 `http://127.0.0.1:8000/openapi.json`
- Knife4j / Swagger UI 页面 URL，例如 `http://192.168.0.203:8083/doc.html`
- 单接口页面 URL，例如 `http://192.168.0.203:8083/doc.html#/yingji/雨量监测控制器/add_13`
- OpenAPI/Swagger JSON 内容
- curl 文本
- 接口路径，例如 `POST /saw/rainfallmonitor/add`

操作流程：

1. 输入文档名称。
2. 选择输入类型，或使用自动识别。
3. 填写输入内容。
4. 如果文档地址需要登录态，可以从浏览器开发者工具复制 Cookie，填入 Cookie 输入框，不需要填写 `Cookie:` 前缀。
5. 点击“下一步：解析与预览”，进入第 2 步。
6. 可选填写接口路径、请求方法、分组、关键词筛选，并点击“筛选”或“重新解析”。
7. 点击“下一步：选择与编辑”，进入第 3 步。
8. 在左侧接口列表勾选接口。
9. 在右侧详情区域查看请求参数、请求体、响应示例、接口描述和其他信息。
10. 在参数 JSON、Body JSON、响应 JSON 中查看左右代码卡片：左侧为示例 JSON，右侧为 Schema JSON。
11. 使用“展开示例 / 展开 Schema”切换当前操作区；Schema 用于查看完整字段结构，不会自动覆盖用户编辑后的请求数据。
12. 如文档示例和 Schema 不一致，可编辑示例 JSON 并点击“保存预览修改”。
13. 点击“保存选中接口”“保存全部接口”或“保存并下一步”，进入导入结果页。

说明：

- 导入后不会自动生成测试用例。
- 测试用例生成必须由用户选择接口后触发。
- 如果只有接口路径且找不到已有资产，只会创建待完善接口草稿。
- Cookie 只用于本次导入请求，默认不保存到数据库。
- 当前不支持自动登录、验证码、SSO、登录页跳转或浏览器自动化登录。
- 如果仍返回 401/403，请确认 Cookie 是否正确、是否过期，并确认 Cookie 属于当前文档系统。
- 文档示例与 Schema 结构可能存在差异，请以实际接口定义和编辑后的请求数据为准。
- 用户编辑后的 JSON 优先用于保存接口资产，并继续用于后续 mock AI 测试用例生成。
- 保存后的接口资产会继续用于 AI mock 测试用例生成。

## 9. 查看接口资产

1. 进入接口列表页。
2. 查看接口名称、方法、路径、分组、鉴权和状态。
3. 进入接口详情页查看 headers、query params、path params、body、response、examples。

## 10. 生成 mock AI 测试用例

1. 进入 AI 用例生成页。
2. 选择接口。
3. 点击生成。
4. 查看生成的 `normal`、`exception`、`boundary`、`auth` 用例。

当前 AI 为 mock，不调用真实大模型，不生成自由 Python 代码。

## 11. 管理测试用例

1. 进入测试用例管理页。
2. 查看、编辑或禁用测试用例。
3. 可编辑请求参数、断言规则和变量。

## 12. 执行测试

1. 进入执行报告页。
2. 选择环境。
3. 多选一个或多个测试用例。
4. 点击执行测试。
5. 在执行结果表中展开单条用例。
6. 查看请求参数 JSON、响应体 JSON、curl 命令和断言结果。
7. 可分别复制请求参数、响应体、curl 或断言结果，用于问题排查和接口复现。
8. 如果响应是 HTTP 200 但业务 `code` 或 `success` 表示失败，执行结果会被业务断言判定为失败。

生成工程位置：

```text
storage/generated/project_{project_id}/execution_{task_id}/
```

## 13. 查看执行结果和报告

执行数据写入：

```text
execution_task
execution_result
test_report
```

报告位置：

```text
storage/reports/execution_{task_id}/report.html
```

日志位置：

```text
storage/logs/execution_{task_id}/pytest.log
```

执行报告页同时展示：

- 执行结果列表。
- 单条用例状态、状态码、耗时和错误信息。
- 单条用例展开后的请求参数 JSON、响应体 JSON、curl 命令。
- 单条用例展开后的业务断言结果。
- 请求参数、响应体、curl、断言结果的复制按钮。
- 报告中的 token / cookie 会脱敏显示，不展示完整敏感值。

## 14. 演示结论

当前版本已跑通接口导入、接口资产管理、mock AI 用例生成、测试用例管理、环境级鉴权配置、Pytest + Requests 执行、业务断言和测试报告查看的 MVP 闭环，适合演示和继续迭代。
