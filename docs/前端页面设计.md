# 前端页面设计

## 当前状态

前端已完成 Vue3 + TypeScript + Vite + Element Plus MVP 页面。第 9 阶段已增强接口导入页，支持多形态接口输入、预览、筛选、编辑确认和保存。第 10 阶段已增强环境配置页和执行报告页，支持环境级鉴权配置、业务断言结果展示和脱敏 curl。

## 技术栈

- Vue3
- TypeScript
- Vite
- Element Plus
- Vue Router
- Pinia
- Axios

## 第 9 阶段接口导入页能力

接口导入页支持：

- 在线 OpenAPI/Swagger JSON URL
- Knife4j / Swagger UI 的 `doc.html`、`swagger-ui.html`、`swagger-ui/index.html`
- 单接口文档页面 URL
- 接口路径输入
- 请求方法筛选
- 接口名称、分组、关键词筛选
- Swagger/OpenAPI JSON 内容
- curl 文本
- Cookie 输入框，用于访问需要登录态的 Knife4j / Swagger 文档
- 顶部四步向导：选择导入方式、解析与预览、选择与编辑、导入结果
- 四个步骤单独展示页面内容，切换步骤时保留已填写输入、Cookie、筛选条件、已解析接口、勾选状态和已保存的 JSON 预览修改
- 解析成功提示区域：文档类型、文档地址、真实文档地址、分组、接口数量、解析耗时
- 左侧接口列表，支持勾选、全选、已选数量和清空
- 右侧接口详情，展示接口基础信息、operationId、鉴权开关和详情 Tabs
- 参数 JSON、Body JSON、响应 JSON 支持“展开示例 / 展开 Schema”切换
- 第 3 步“选择与编辑”中，参数 JSON、Body JSON、响应 JSON 使用 `JsonPreviewEditor.vue` 统一展示为左右代码卡片：左侧为可执行示例 JSON，右侧为展开后的 Schema JSON
- JSON 展示区包含标题、数据类型、展示说明、行号、等宽字体、复制、格式化和保存预览修改

页面交互：

- 仅预览，不保存
- 保存选中接口
- 保存全部接口
- 清空预览
- 勾选接口
- 编辑确认接口基础信息和 JSON 字段
- 复制、格式化、编辑和保存预览 JSON
- 第 3 步提供左侧接口列表和右侧接口详情编辑区，支持参数 JSON、Body JSON、响应 JSON 的“展开示例 / 展开 Schema”切换
- 展开示例用于编辑可执行请求或响应示例，展开 Schema 用于查看完整字段结构
- 用户编辑后的 JSON 优先用于保存接口资产，并继续用于后续 mock AI 测试用例生成
- Schema 展开只用于查看和按需保存结构，不会自动覆盖用户编辑后的可执行请求 JSON

页面边界：

- 导入后不会自动生成测试用例。
- 测试用例生成必须由用户在 AI 用例生成页主动触发。
- Cookie 可从浏览器开发者工具复制，填写时不需要 `Cookie:` 前缀。
- Cookie 只用于本次预览或保存请求，默认不保存。
- 不支持自动登录、验证码、SSO、登录页跳转或浏览器自动化登录。
- 文档示例与 Schema 展开结果可能存在差异，页面会提示用户以实际接口定义和编辑后的请求数据为准。
- 展开示例用于参考和快速请求，展开 Schema 用于查看完整字段结构。
- 第 3 步前端会将每个接口预览对象适配为 `params_example_json`、`params_schema_json`、`params_edit_json`、`body_example_json`、`body_schema_json`、`body_edit_json`、`response_example_json`、`response_schema_json`、`response_edit_json`，避免示例和 Schema 混用。
- AI 辅助解析当前为 mock，只做提示，不直接编造接口参数。
- 前端不直接连接 MySQL。
- 前端不直接执行 Pytest。
- 前端不直接请求被测接口，所有操作都通过后端 API 完成。

## 执行报告页能力

执行结果 / 测试报告页支持：

- 选择环境。
- 多选测试用例筛选并执行。
- 展示执行任务状态、总数、通过数、失败数、跳过数。
- 展示报告路径、日志路径和生成工程路径。
- 执行结果表支持单条用例展开。
- 展开区域展示请求参数 JSON、响应体 JSON 和 curl 命令。
- 展开区域展示断言结果。
- 请求参数、响应体、curl 和断言结果均支持单独复制。
- curl 优先使用后端保存的脱敏 curl，避免暴露完整 token / cookie。

## 环境配置页能力

第 10 阶段环境配置页支持：

- 配置 `base_url`。
- 配置环境公共 `headers_json`。
- 配置 `auth_type`，支持 `none`、`bearer`、`token`、`cookie`、`custom`。
- 配置 Token。
- 配置 Cookie。
- 配置 `auth_config_json`，用于扩展 token header、token prefix、自定义鉴权 headers。
- 配置 `timeout_seconds`。
- 配置 `retry_count`。

页面边界：

- Token 和 Cookie 通过后端环境接口保存到 `environment.variables`，用于后端执行测试。
- 前端不直接请求被测接口，不直接执行 Pytest。
- 前端执行报告页展示的是后端保存的脱敏请求数据，不展示完整 token / cookie。
- 当前不支持自动 token 刷新、登录页跳转、验证码、SSO 或浏览器自动化登录。

页面边界：

- 前端不直接执行 Pytest，执行仍通过后端 `POST /api/v1/executions/run` 完成。
- 前端不直接请求被测接口，curl 仅作为复制和排查使用。
- 展开/收起结果行不会修改执行结果数据。
