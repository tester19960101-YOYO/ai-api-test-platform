- 后端通过 `backend/app/core/assertion_dsl.py` 完成 DSL 与内部结构化断言互转。

- 用户断言优先级最高，AI 建议默认不直接决定 pass/fail。
- 第11阶段真实 AI 输出中的断言统一标准化为 DSL 字符串。

## 第11阶段断言规则（历史兼容说明）

以下 `test_cases` 示例为第11阶段早期兼容结构，后端仍可在兼容路径中识别，但当前主提示词规范已经迁移到 `test_strategy`：

```json
{
  "test_cases": [
    {
      "type": "normal",
      "request": {},
      "assertions": [
        {"type": "status_code", "expected": 200},
        {"type": "dsl", "expression": "$.code == 200"}
      ]
    }
  ]
}
```

标准化后：

- `status_code` 断言会转换为 `status_code == 200`。
- `dsl.expression` 会保留为 DSL 字符串。
- DSL 会经过解析校验，非法 DSL 不允许入库。
- 标准化后的 DSL 保存到 `test_case.dsl_assertions`。

## 注意事项

- AI 不生成自由 Python 代码。
- JSON 结构只用于后端执行层和 AI 输出校验，用户侧仍以 DSL 为主。
- 本阶段不修改 execution_engine，不改变现有执行接口返回结构。
## 第11阶段当前断言输出格式

真实 AI 用例生成返回的断言必须统一为 DSL 字符串数组，不再接受复杂对象结构或 `suggestions` 结构作为入库格式。

当前权威 AI 输出外层结构为 `test_strategy`，包含 `normal`、`error`、`boundary`、`security` 四类策略用例。每条用例的 `assertions` 字段必须是 DSL 字符串数组。

标准格式：

```json
{
  "assertions": [
    "status_code == 200",
    "$.code == 200",
    "$.data != null"
  ]
}
```

执行与保存规则：

- AI 生成的 DSL 断言保存到 `test_case.dsl_assertions`。
- `test_case.assertions` 保存由 DSL 转换得到的内部结构化断言，用户仍通过 DSL 编辑断言。

## TestCaseUnifiedModel v1 中的断言字段

当前测试用例统一模型中，断言相关字段分为两层：

- `dsl_assertions`：用户侧展示和编辑的 DSL 字符串数组。
- `assertions`：由 DSL 解析得到的内部结构化断言，供执行引擎融合和执行。

前端不要求用户手写结构化 JSON 断言；执行层仍会保留 `source`、`path`、`operator`、`expected` 等字段用于断言追踪。
- DSL 在入库前会调用 `backend/app/core/assertion_dsl.py` 校验。
- 非法 DSL、空断言、对象断言、非 JSON 输出均会导致生成失败，且不会保存半成品。
- 不允许 AI 生成写死的 `business_code == 1`。

本次修复不改变 DSL 语法，不修改 execution_engine。
