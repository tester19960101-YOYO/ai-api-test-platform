# 断言系统设计

## 当前阶段

- 第10阶段：鉴权 + 基础断言（已完成）
- 第10.1阶段：DSL + AI断言融合（已完成）
- 第10.2阶段：执行引擎可观测（已完成/稳定）
- 第11阶段：真实 AI 用例生成与 DSL 断言自动生成（已完成）

## 已完成能力

- 用户侧断言语言使用 DSL，例如 `$.code == 200`、`$.data != null`、`status_code == 200`。
- 后端通过 `backend/app/core/assertion_dsl.py` 完成 DSL 与内部结构化断言互转。
- 后端通过 `backend/app/core/assertion_engine_v2.py` 融合 Swagger、AI、用户三类断言。
- AI 断言作为建议层保存到 `test_case.variables.ai_assertion_dsl`。
- 用户断言优先级最高，AI 建议默认不直接决定 pass/fail。
- 第11阶段真实 AI 输出中的断言统一标准化为 DSL 字符串。

## 第11阶段断言规则

AI 大模型输出标准：

```json
{
  "test_cases": [
    {
      "type": "normal",
      "request": {},
      "assertions": [
        {"type": "status_code", "expected": 200},
        {"type": "dsl", "expression": "$.code == 200"}
      ]
    }
  ]
}
```

标准化后：

- `status_code` 断言会转换为 `status_code == 200`。
- `dsl.expression` 会保留为 DSL 字符串。
- DSL 会经过解析校验，非法 DSL 不允许入库。
- 标准化后的 DSL 保存到 `test_case.variables.ai_assertion_dsl`。

## 注意事项

- AI 不生成自由 Python 代码。
- JSON 结构只用于后端执行层和 AI 输出校验，用户侧仍以 DSL 为主。
- 本阶段不修改 execution_engine，不改变现有执行接口返回结构。
## 第11阶段专项修复：AI 断言输出格式

真实 OpenAI 用例生成返回的断言必须统一为 DSL 字符串数组，不再接受复杂对象结构或 `suggestions` 结构作为入库格式。

标准格式：

```json
{
  "assertions": [
    "status_code == 200",
    "$.code == 200",
    "$.data != null"
  ]
}
```

执行与保存规则：

- AI 生成的 DSL 断言保存到 `test_case.variables.ai_assertion_dsl`。
- `test_case.assertions` 仍由用户控制，AI 不直接写入用户断言。
- DSL 在入库前会调用 `backend/app/core/assertion_dsl.py` 校验。
- 非法 DSL、空断言、对象断言、非 JSON 输出均会导致生成失败，且不会保存半成品。
- 不允许 AI 生成写死的 `business_code == 1`。

本次修复不改变 DSL 语法，不修改 execution_engine。
