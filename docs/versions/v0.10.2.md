# v0.10.2

## 一、本次变更

- DSL 断言系统上线。
- AI / Swagger / 用户断言统一为 DSL 表达。
- 新增可视化断言编辑器。
- 支持 DSL 与内部 JSON 断言结构双向转换。
- 执行引擎适配 DSL 输入，执行层仍使用结构化断言。
- AI 断言输出简化为 DSL 字符串列表。

## 二、新增模块

- `backend/app/core/assertion_dsl.py`
- `backend/app/api/v1/assertion_api.py`
- `backend/app/schemas/assertion.py`
- `frontend/src/components/AssertionDslBuilder.vue`

## 三、新增接口

```text
POST /api/v1/assertion/parse
POST /api/v1/assertion/to-dsl
```

兼容别名：

```text
POST /api/assertion/parse
POST /api/assertion/to-dsl
```

## 四、DSL 标准

支持表达：

```text
$.code == 200
$.data != null
status_code == 200
$.msg contains 成功
```

支持操作：

```text
==  !=  >  <  contains  exists  not null
```

## 五、核心规则变化

- DSL 是唯一用户断言语言。
- JSON 断言结构只存在执行层和接口转换结果中。
- AI mock 输出 `assertions: string[]`，例如 `["$.code == 200"]`。
- AI 断言保存到 `variables.ai_assertion_dsl`，默认不控制 pass/fail。
- 用户从 AI / Swagger 区点击插入后，DSL 才进入用户断言并参与执行。
- Swagger 基础断言展示为 DSL，例如 `status_code == 200`、`$.data != null`。

## 六、影响范围

- 测试用例编辑页
- 接口详情页 Swagger 断言展示
- AI mock 用例生成
- 执行引擎断言收集与转换
- 断言解析 API

## 七、兼容性

- 向下兼容 `v0.10.1` 的结构化断言。
- 不影响接口导入。
- 不影响环境鉴权配置。
- 不修改数据库结构。
- 不接入真实 AI 大模型。
