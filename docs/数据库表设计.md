# 数据库表设计

## 当前阶段统一口径

- 第10阶段：鉴权 + 基础断言（已完成）
- 第10.1阶段：DSL + AI断言融合（已完成）
- 第10.2阶段：执行引擎可观测（已完成/稳定）

说明：第10.2阶段当前以执行稳定性、错误兜底、请求/响应/断言结果留痕、日志与报告路径可查看为准；当前不提供独立追踪编号或单独查询接口。

## 基础规范

- 数据库：MySQL 8.0
- 存储引擎：InnoDB
- 字符集：utf8mb4
- 主键：`BIGINT AUTO_INCREMENT`
- 时间字段：所有核心表包含 `created_at` / `updated_at`
- 复杂字段：使用 JSON 类型保存请求结构、响应结构、变量、断言、AI 输出、执行配置等复杂数据
- 表和字段需要 COMMENT

## 9 张核心表

- `project`：项目表，保存测试项目基础信息。
- `environment`：环境配置表，保存项目下的 base_url、变量、公共请求头和环境状态。
- `api_document`：接口文档表，保存导入来源、原始内容和解析结果。
- `api_endpoint`：接口资产表，保存接口名称、分组、方法、路径、请求头、请求参数、请求体、响应结构、示例、鉴权状态和接口状态。
- `test_case`：测试用例表，保存测试步骤、断言、变量和用例状态。
- `execution_task`：执行任务表，保存一次测试执行任务、状态、统计和执行配置。
- `execution_result`：执行结果表，保存每条用例的请求、响应、断言、耗时和错误信息。
- `test_report`：测试报告表，保存测试报告元数据和报告路径。
- `ai_analysis_record`：AI 分析记录表，保存 AI 用例生成和后续 AI 分析记录。

## 第 9 阶段数据库说明

第 9 阶段未新增数据库表，未修改数据库字段，仍使用 9 张核心表。

第 9 阶段数据保存规则：

- 原始输入内容保存到 `api_document.raw_content`。
- 解析结果和第 9 阶段元信息保存到 `api_document.parsed_data`。
- 保存确认后的接口资产写入 `api_endpoint`。
- 参数 JSON 保存到 `api_endpoint.request_params`，区分 `query`、`path`、`header`、`cookie`。
- Body Schema、Body 示例和原始 schema 元信息复用 `api_endpoint.request_body_schema` 和 `api_endpoint.example_request` 保存。
- 响应 Schema、响应示例和按 status code 展开的响应信息复用 `api_endpoint.response_schema` 和 `api_endpoint.example_response` 保存。
- 当前未新增 `schema_json`、`raw_schema_json` 独立字段。
- 只有接口路径且找不到已有资产时，可保存 `status = draft` 的待完善接口草稿。
- 不会在接口导入后自动生成 `test_case`。
- AI 辅助解析当前为 mock，不新增 `ai_analysis_record`。

## 第 10 阶段数据库说明

第 10 阶段未新增数据库表，未新增数据库字段，仍使用 9 张核心表。

字段使用约定增强：

- `environment.headers`：保存环境公共请求头。
- `environment.variables.auth_type`：保存鉴权类型，例如 `none`、`bearer`、`token`、`cookie`、`custom`。
- `environment.variables.token`：保存环境级 token，用于执行测试时组装请求头。
- `environment.variables.cookie`：保存环境级 Cookie，用于执行测试时组装请求头。
- `environment.variables.auth_config_json`：保存扩展鉴权配置，例如 `token_header`、`token_prefix`、自定义 headers。
- `environment.variables.timeout_seconds`：保存环境默认超时时间。
- `environment.variables.retry_count`：保存环境默认重试次数。
- `execution_result.request_data`：保存脱敏后的有效请求数据和 curl 命令。
- `execution_result.response_data`：保存 JSON 响应；非 JSON 响应保存 `raw_text`、`content_type`、`json_parse_error`。
- `execution_result.assertion_result`：保存 HTTP 断言和业务断言的执行结果。

安全边界：

- 执行报告和日志不保存完整 token / cookie，只保存脱敏后的请求头和 curl。
- 当前未实现 token/cookie 加密存储；生产化前需要补充敏感信息加密存储方案。

## 第 10.1 阶段数据库说明

第 10.1 阶段未新增数据库表，未新增数据库字段，仍使用 9 张核心表。

字段使用约定增强：

- `test_case.assertions`：保存用户断言。第 10.1 阶段起优先保存 DSL 字符串数组，也兼容旧版结构化断言格式。
- `test_case.variables.ai_assertion_dsl`：保存 AI 生成的 DSL 断言建议，AI 建议默认不控制 pass/fail。
- `api_endpoint.response_schema`：用于生成 Swagger/OpenAPI 基础断言，包括状态码、业务 code 和 required 字段。
- `execution_result.assertion_result`：保存断言系统 2.0 的执行结果，包括 `final_assertions`、每条断言来源、跳过原因和失败原因。

第 10.1 阶段安全边界：

- 不保存真实 AI 密钥。
- 不新增敏感鉴权字段。
- 不改变 token / cookie 脱敏保存规则。
- 断言来源只记录 `user`、`swagger`、`ai`，不保存额外敏感上下文。

## 核心路径与表关系

- 接口导入：`api_document` -> `api_endpoint`
- AI 用例生成：`api_endpoint` -> `test_case`，记录到 `ai_analysis_record`
- 执行测试：`test_case` -> `execution_task` / `execution_result` / `test_report`

- 未新增接口依赖关系表。
- 未新增用户、角色、权限表。
