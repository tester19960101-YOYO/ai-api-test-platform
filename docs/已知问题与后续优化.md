# 已知问题与后续优化

## 当前已知问题

- 前端未单独配置 lint 命令，当前主要通过 `npm run build` 完成类型检查和构建验证。
- 前端生产构建存在 chunk 超过 500 kB 的提示，当前不影响 MVP 演示。
- 如果当前终端没有继承 MySQL PATH，需要重启终端或使用 MySQL CLI 绝对路径。
- 当前演示数据主要用于本地验证，未提供生产级种子数据管理。

## 当前限制

- AI 仍为 mock。
- 未接真实大模型。
- AI 辅助解析不会从 HTML 页面凭空生成完整接口参数。
- 接口导入页已支持临时 Cookie 抓取需要登录态的 Knife4j / Swagger 文档，但不支持自动登录、验证码、SSO 或浏览器自动化登录。
- Cookie 只在本次导入请求中使用，默认不保存；如果 Cookie 过期，需要用户重新复制。
- 未实现复杂接口依赖编排。
- 未实现复杂 token 自动刷新。
- 未实现 Word/PDF 解析。
- 未实现 CI/CD。
- 未实现权限系统。
- 未实现多用户协作。
- 未实现 WebSocket 实时日志。
- 未实现生产级部署方案。
- 未实现 SSO、验证码或扫码登录。
- 未实现并发压测。
- 未实现复杂 Allure 报告。
- 未实现 httpx 异步执行。

## 已完成的第 9 阶段增强

- 支持输入 Knife4j / Swagger UI 的 `doc.html` 页面地址。
- 自动尝试发现真实 OpenAPI/Swagger JSON 地址。
- 支持在线接口文档 URL 抓取和解析。
- 支持填写 Cookie 解决部分需要登录态的接口文档 401 问题。
- 支持单接口文档页面 URL hash hint 筛选。
- 支持接口路径、请求方法、名称、分组、关键词筛选。
- 支持仅预览、保存选中、保存全部。
- 支持基础 `$ref` 展开和参数 / Body / 响应 JSON 示例生成。
- 支持“展开示例 / 展开 Schema”切换。
- 支持接口导入第 3 步将请求参数、请求体、响应示例分开展示为示例 JSON 和 Schema JSON。
- 支持用户编辑后的 JSON 优先保存，Schema 展开仅用于查看完整字段结构，不自动覆盖可执行请求数据。
- 支持用户编辑预览 JSON 后保存接口资产。
- AI 仅作为 mock 辅助提示，不凭空编造参数。

## 已完成的执行报告页增强

- 支持在执行报告页多选测试用例并执行。
- 支持展开单条执行结果查看请求参数 JSON、响应体 JSON 和 curl 命令。
- 支持分别复制请求参数、响应体和 curl，便于复现接口请求和排查失败原因。
- 展开信息仅用于查看和复制，不修改执行结果或测试用例。

## 已完成的第 10 阶段增强

- 支持环境级鉴权配置，包括鉴权类型、Token、Cookie、公共 headers、`auth_config_json`、timeout 和 retry。
- 执行测试时自动合并环境公共 headers、环境鉴权 headers 和测试用例请求 headers。
- 支持业务断言 `business_code`、`business_success`、`json_path_not_empty`。
- 响应 JSON 中存在 `code` 或 `success` 时自动补充默认业务断言，避免 HTTP 200 但业务失败被误判为通过。
- 执行结果保存脱敏后的请求参数、响应体、curl 命令和断言结果。
- 非 JSON 响应会保存原始文本和 JSON 解析错误提示。
- 报告和日志中不输出完整 token / cookie。

## 已完成的第 10.1 阶段增强

- 新增断言系统 2.0 融合引擎，统一处理用户断言、Swagger/OpenAPI 基础断言和 mock AI 断言建议。
- 用户断言拥有最高优先级，Swagger/OpenAPI 断言作为基础层，AI 断言仅作为建议层。
- mock AI 不再决定测试结果，只输出结构化建议断言和 `confidence`。
- `business_code` 不再写死为 1，支持 `success_codes` 和 `success_expression`。
- `$.data` 相关 JSONPath 断言仅在业务成功后执行，避免业务失败响应导致误判。
- 执行结果中保存最终融合断言和断言来源，便于追踪失败原因。
- 前端测试用例编辑区增加 AI 断言建议、Swagger 断言和融合断言预览。
- `v0.10.2` 新增断言 DSL 可视化系统，用户不再手写 JSON 断言。
- AI / Swagger / 用户断言统一展示为 DSL。
- 新增 DSL 解析和 JSON 转 DSL 接口。

当前限制补充：

- Swagger/OpenAPI 断言当前为基础层，主要覆盖状态码、业务 code 和 required 字段，复杂 schema 深度校验后续可继续增强。
- mock AI 断言建议不控制 pass/fail；真实 AI 大模型接入仍属于后续阶段。
- 断言系统 2.0 不改变数据库结构，断言仍通过现有 JSON 字段保存。
- DSL 可视化系统当前不做复杂表达式编辑器，不支持括号组合、AND/OR 复合条件。

## 已修复问题记录

- 已修复 `POST /api/v1/executions/run` 在部分 DSL / JSONPath / pytest 结果异常场景下可能返回 HTTP 500 的问题。
- 已增加 DSL 执行容错：DSL 解析失败、JSONPath 为空或非法、响应非 JSON、断言执行异常会转换为 failed 结果。
- 已增加 pytest runner 容错：pytest 超时和 `results.jsonl` 单行损坏会转换为 failed 结果。
- 已修复生成的 Pytest client 模板中 Header 合并注释与代码同处一行导致 `headers` 变量未定义的风险。

当前限制补充：

- 执行引擎已避免非系统级异常直接造成 run 接口 500，但数据库不可用、进程被强制终止等系统级异常仍可能返回接口错误。
- 当前未新增链路追踪、指标采集或 Debug 回放能力。
