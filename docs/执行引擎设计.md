# 执行引擎设计

## 当前阶段说明

当前项目已完成到第八阶段，MVP 基线版本为 `v0.1.0-mvp`。当前已实现 Pytest + Requests 基础执行引擎，并已通过 MVP 联调验收调用执行接口。

当前执行引擎能力是 MVP 基础闭环：

- 从数据库读取项目、环境、接口资产和测试用例
- 使用 Jinja2 渲染临时 Pytest 工程
- 使用 Requests 执行 HTTP 请求
- 使用 Pytest 调用测试用例
- 使用 pytest-html 生成 HTML 报告
- 保存执行任务、执行结果和测试报告元信息

## 模块位置

```text
backend/app/generator
backend/app/runner
```

Pytest 工程模板位置：

```text
backend/app/generator/templates/pytest_project
```

## 模板文件

当前模板包括：

```text

core/assertion.py.j2

core/logger.py.j2

```

## 生成与输出位置

生成出来的测试工程位置：

```text
storage/generated/project_{project_id}/execution_{task_id}/
```

测试报告位置：

```text
storage/reports/execution_{task_id}/report.html
```

执行日志位置：

```text
storage/logs/execution_{task_id}/pytest.log
```

上传文件位置：

```text
storage/uploads
```

## 代码放置约束

生成出来的测试代码不要放进：

```text
backend/app
```

`backend/app` 只保存平台自身后端代码。生成出来的测试工程必须放在 `storage/generated`。

## 请求能力

当前基础请求封装使用 Requests，支持：

- GET
- POST
- PUT
- DELETE
- PATCH
- base_url
- headers
- query params
- JSON body
- timeout

## 断言能力

当前基础断言模块支持：

- `status_code`
- `json_path_equal`
- `json_path_not_null`
- `json_path_contains`
- `response_time`

JSONPath 读取能力由 `jsonpath-ng` 提供。

## 执行 API

```text
POST /api/v1/executions/run
```

当前支持：

- 按 `project_id` 执行
- 按 `environment_id` 执行
- 按 `case_ids` 执行
- MVP 阶段优先支持单接口用例和用例列表执行

## 执行数据

执行任务保存到：

```text
execution_task
```

执行结果保存到：

```text
execution_result
```

测试报告保存到：

```text
test_report
```

## 当前限制

- 当前仍为 mock AI，不接真实大模型。
- 不做 AI 失败分析。
- 不做复杂接口依赖编排。
- 不做复杂 token 自动刷新。
- 不做 SSO、验证码、扫码登录。
- 不做 httpx 异步执行。
- 不做并发压测。
- 不做 CI/CD。
- 不做复杂 Allure 报告，MVP 使用 pytest-html。
- 不做 WebSocket 实时日志。
- 不做生产级复杂前端交互和可视化编排。
