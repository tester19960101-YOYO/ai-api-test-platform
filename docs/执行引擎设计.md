# 执行引擎设计

## 当前阶段说明

当前项目已完成到第 10.1 阶段，MVP 基线版本为 `v0.1.0-mvp`，第 9 阶段收尾版本标记为 `v0.1.0-stage9`，第 10 阶段归档版本为 `v0.10.0`。当前已实现 Pytest + Requests 基础执行引擎，并完成断言系统2.0融合引擎。

当前执行引擎能力是 MVP 基础闭环：

- 从数据库读取项目、环境、接口资产和测试用例
- 使用 Jinja2 渲染临时 Pytest 工程
- 使用 Requests 执行 HTTP 请求
- 使用 Pytest 调用测试用例
- 使用 pytest-html 生成 HTML 报告
- 保存执行任务、执行结果和测试报告元信息

## 代码放置约束

生成出来的测试代码不要放进：

```text
backend/app
```

`backend/app` 只保存平台自身后端代码。生成出来的测试工程必须放在 `storage/generated`。

## 请求能力

当前基础请求封装使用 Requests，支持：

- GET
- POST
- PUT
- DELETE
- PATCH
- base_url
- headers
- query params
- JSON body
- timeout
- retry_count
- 环境公共 headers
- 环境级 token / cookie / 自定义鉴权 headers

请求头合并优先级：

```text
环境公共 headers < 环境鉴权 headers < 测试用例请求 headers
```

如果环境 Cookie 和用例 Cookie 同时存在，会合并为同一个 `Cookie` 请求头。

## 断言能力

当前断言系统2.0支持：

- `status_code`
- `business_code`
- `json_path`
- `response_time`

JSONPath 读取能力由 `jsonpath-ng` 提供。

统一断言结构：

```json
{
  "id": "string",
  "source": "swagger | ai | user",
  "type": "status_code | json_path | business_code",
  "path": "$.code",
  "operator": "== | != | exists | contains",
  "expected": 200,
  "priority": 1,
  "enabled": true
}
```

融合规则：

- 收集 Swagger、AI、用户三层断言。
- 优先级排序：`user > swagger > ai`。
- 同 path 去重，保留最高优先级。
- AI 断言默认禁用，仅作为建议和追踪信息。
- 最终执行 `final_assertions`。

business_code 规则：

- 不再写死 `business_code = 1`。
- 支持 `success_codes`，例如 `[200, 0]`。
- 支持 `success_expression`，例如 `$.code == 200`。
- `$.data` 相关断言仅在业务成功后执行。

## 执行 API

```text
POST /api/v1/executions/run
```

当前支持：

- 按 `project_id` 执行
- 按 `environment_id` 执行
- 按 `case_ids` 执行
- MVP 阶段优先支持单接口用例和用例列表执行

## 执行数据

执行任务保存到：

```text
execution_task
```

执行结果保存到：

```text
execution_result
```

测试报告保存到：

```text
test_report
```

第 10 阶段执行结果保存增强：

- `request_data` 保存脱敏后的有效请求数据和 curl 命令。
- `response_data` 保存 JSON 响应；非 JSON 响应保存原始文本、Content-Type 和 JSON 解析错误提示。
- `assertion_result` 保存每条断言的通过状态和失败原因。
- 不在报告或日志中输出完整 token / cookie。

第 10.1 阶段执行结果保存增强：

- `assertion_result.final_assertions` 保存最终融合断言。
- 每条断言保留 `source`，可追踪来源为 `ai`、`swagger` 或 `user`。
- 被禁用的 AI 建议会标记为 skipped，不参与最终 pass/fail。

## 当前限制

- 当前仍为 mock AI，不接真实大模型。
- 不做 AI 失败分析。
- 不做复杂接口依赖编排。
- 不做复杂 token 自动刷新。
- 不做 SSO、验证码、扫码登录。
- 不做 httpx 异步执行。
- 不做并发压测。
- 不做 CI/CD。
- 不做复杂 Allure 报告，MVP 使用 pytest-html。
- 不做 WebSocket 实时日志。
- 不做生产级复杂前端交互和可视化编排。
