# 后端接口设计

## 统一响应格式

当前 MVP 基线版本为 `v0.1.0-mvp`。第八阶段仅做基线固化与演示准备，未新增或调整后端 API。

所有接口使用统一响应格式：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

## 第三阶段已实现接口

Swagger/OpenAPI JSON 内容或直接 OpenAPI JSON URL 导入：

```text
POST /api/v1/projects/{project_id}/api-documents/openapi
```

Swagger/OpenAPI JSON 文件导入：

```text
POST /api/v1/projects/{project_id}/api-documents/openapi-file
```

curl 文本导入：

```text
POST /api/v1/projects/{project_id}/api-documents/curl
```

说明：

- 原始内容保存到 `api_document.raw_content`。
- 解析结果保存到 `api_document.parsed_data`。
- 解析后的接口保存到 `api_endpoint`。
- 当前仅支持直接返回 OpenAPI JSON 的 URL。
- 暂不支持输入 Knife4j / Swagger UI 的 `doc.html` 页面地址并自动识别真实接口文档地址。
- 暂未实现在线接口文档 URL 导入与 AI 辅助解析，该能力规划到第 9 阶段。
- 不做 Word/PDF 解析。
- 不做 token/cookie 自动补全。

## 第四阶段已实现接口

AI mock 用例生成：

```text
POST /api/v1/endpoints/{endpoint_id}/testcases/generate
```

说明：

- 根据 `api_endpoint` 生成 mock 测试用例。
- 当前是 mock AI，不调用真实大模型。
- AI 输出为结构化 JSON。
- 输出经过 schema 校验后再入库。
- 生成 `normal`、`exception`、`boundary`、`auth` 四类用例。
- 生成的测试用例保存到 `test_case`。
- mock AI 调用记录保存到 `ai_analysis_record`。

## 第五阶段已实现接口

Pytest + Requests 执行：

```text
POST /api/v1/executions/run
```

请求体示例：

```json
{
  "project_id": 1,
  "environment_id": 1,
  "case_ids": [1],
  "timeout": 10
}
```

说明：

- 按 `project_id`、`environment_id` 和可选 `case_ids` 执行测试用例。
- 生成临时 Pytest 工程到 `storage/generated/project_{project_id}/execution_{task_id}/`。
- 使用 subprocess 调用 Pytest。
- 使用 pytest-html 生成报告。
- 执行日志保存到 `storage/logs/execution_{task_id}/pytest.log`。
- 报告保存到 `storage/reports/execution_{task_id}/report.html`。
- 执行任务保存到 `execution_task`。
- 每条用例执行结果保存到 `execution_result`。
- 测试报告元信息保存到 `test_report`。

响应数据包含：

```text
task
results
report
generated_project_path
report_path
log_path
pytest_exit_code
stdout
stderr
```
