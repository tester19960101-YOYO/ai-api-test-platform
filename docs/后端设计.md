# 后端设计

## 当前版本

当前后端基于 FastAPI + SQLAlchemy + Alembic + Pydantic，数据库使用 MySQL 8.0。第11阶段专项修复后，AI 用例生成链路已切换为真实 OpenAI Python SDK 调用。

## 已完成能力

- 项目、环境、接口资产、测试用例基础 CRUD。
- OpenAPI/Swagger/curl/在线文档导入与解析。
- `POST /api/v1/endpoints/{endpoint_id}/testcases/generate` 真实 OpenAI 用例生成。
- Pytest + Requests 基础执行引擎。
- DSL 断言系统与执行结果保存。

## AI 用例生成链路

```text
POST /api/v1/endpoints/{endpoint_id}/testcases/generate
  -> 查询 api_endpoint
  -> 构建接口结构化模型
  -> CoverageEngine 生成 coverage_matrix 和 coverage_targets
  -> LLMFactory 创建 OpenAIClient 或 QwenClient
  -> 调用模型按覆盖维度生成 test_strategy
  -> 校验 test_strategy 和 coverage_dimension
  -> 标准化为可执行 test_case
  -> 写入 test_case
  -> 写入 ai_analysis_record
```

Coverage Engine 位置：

```text
backend/app/services/coverage_engine.py
```

当前覆盖矩阵包含 `functional`、`validation`、`boundary`、`negative`、`security`、`business`、`dependency` 七个维度。生成接口返回 `coverage_matrix` 和 `coverage_summary`，用于说明本次 AI 生成的覆盖情况。

OpenAI 客户端位置：

```text
backend/app/ai/clients/openai_client.py
```

兼容导出位置：

```text
backend/app/ai/llm_client.py
```

## 配置说明

```text
AI_API_KEY=sk-xxxx
AI_API_BASE_URL=https://api.openai.com/v1
AI_MODEL_NAME=gpt-4o-mini
AI_REQUEST_TIMEOUT=60
```

`AI_API_KEY` 缺失时，生成接口返回明确配置错误，不生成 mock 用例，不写入 `test_case`。

## 注意事项

- mock/fake LLM 仅用于单元测试，不作为运行时兜底。
- OpenAI 输出必须是结构化 JSON。
- AI 生成断言统一使用 DSL 字符串数组。
- 本次专项修复不修改 execution_engine，不改变 DSL 语法，不新增数据库结构。

## 多模型适配层

第11阶段补充统一 LLM 工厂：

```text
backend/app/ai/llm_factory.py
```

工厂根据 `AI_PROVIDER` 创建模型客户端：

- `openai` -> `OpenAIClient`
- `qwen` -> `QwenClient`

Qwen 使用 DashScope OpenAI-compatible mode：

```text
AI_PROVIDER=qwen
AI_API_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
AI_MODEL_NAME=qwen-max-latest
```

OpenAI 使用：

```text
AI_PROVIDER=openai
AI_API_BASE_URL=https://api.openai.com/v1
AI_MODEL_NAME=gpt-4o-mini
```

业务层只调用统一的 `generate_json(system_prompt, user_prompt)`，不直接判断供应商，不直接调用 SDK。

## TestCaseUnifiedModel v1

当前后端已落地统一测试用例模型，覆盖 AI 生成、手工编辑、执行输入和报告展示链路。

实现位置：

```text
backend/app/services/test_case_unified_model.py
backend/app/services/test_case_consistency_service.py
backend/app/schemas/test_case.py
backend/app/models/test_case.py
```

核心规则：

- 新增测试用例写入时统一归一化为 `TestCaseUnifiedModel v1`。
- `request_data` 保存可执行请求。
- `assertions` 保存内部结构化断言。
- `dsl_assertions` 保存用户侧 DSL。
- `coverage_tag`、`risk_level`、`data_dependency`、`ai_metadata` 保存覆盖和追踪信息。
- `steps` / `variables` 仅用于历史兼容，不作为当前主模型。

数据库变更通过 Alembic migration `20260617_01_test_case_unified_model_v1.py` 和 `database/init.sql` 同步维护。
